## English Version

### Overview

**gzcu-thesis-spec-skills** is a Codex skill for undergraduate thesis writing, formatting, and compliance review at **Guangzhou City University of Technology (GZCU)**.

This repository is calibrated against a real submission-ready GZCU `.docx`, not only against abstract school-rule summaries. Its default behavior therefore prefers the chapter organization, Word sectioning pattern, header/footer logic, and citation implementation already proven by a compliant final manuscript.

The skill integrates with:

- **$doc** for `.docx` editing, section breaks, headers, footers, page numbering, TOC refresh, and final Word inspection
- **$drawio** for thesis diagrams such as architecture figures, ER diagrams, and flowcharts
- **$playwright-cli** for browser-based evidence collection, screenshots, and runtime proof

### What This Skill Enforces

- school-specific thesis rules as hard constraints
- a template-compatible 4-section Word model:
  - cover + explanation page
  - Chinese + English abstract
  - TOC
  - main body through acknowledgements
- a submission-compatible 6-chapter default structure for software-engineering theses:
  - Chapter 1 Introduction
  - Chapter 2 Related Technology and Theoretical Basis
  - Chapter 3 System Requirements Analysis
  - Chapter 4 Overall System Design
  - Chapter 5 Detailed Design and Implementation
  - Chapter 6 System Testing and Deployment
- odd-page chapter starts
- Roman/Arabic page-number separation
- body-to-reference Word cross-references as the default final-docx target

### Baseline vs Optional Enhancements

#### Baseline submission requirements

- TOC generated by Word
- correct section breaks and page-number schemes
- correct odd/even header behavior
- clickable body citations pointing to bibliography items in the final `.docx`
- figure/table numbering and in-text references

#### Optional final-docx enhancements

- clickable figure cross-references
- clickable table cross-references
- batch asset insertion and image-block normalization

The compliant sample confirms bibliography jumping as baseline behavior. It does **not** prove that clickable figure/table jumping is mandatory for submission, so those remain opt-in enhancements unless the user explicitly requests them.

### Typical Workflow

1. Collect real project evidence.
2. Build a compliance matrix and evidence map.
3. Draft or revise chapters using the submission-compatible 6-chapter structure by default.
4. Finalize Word section breaks, headers, page numbers, TOC, and bibliography cross-references.
5. Run a final compliance review.

## 中文版本

### 项目概述

**gzcu-thesis-spec-skills** 是面向**广州城市理工学院**本科毕业设计（论文）写作、排版与合规审查的 Codex Skill。

本仓库不是只根据抽象校规写规则摘要，而是额外参考了一份已经验证可提交的 GZCU 终稿 `.docx` 来校准默认行为。因此，Skill 会优先采用这份合规终稿已经证明可行的：

- 章节组织方式
- Word 分节方式
- 页眉页脚逻辑
- 页码切换方式
- 正文引用到参考文献的交叉引用实现

### 核心约束

- 将学校规则作为硬性约束执行
- 默认采用与提交版兼容的 4 段 Word 结构：
  - 封面 + 说明页
  - 中文摘要 + 英文摘要
  - 目录
  - 正文至致谢
- 软件工程论文默认采用与提交版兼容的 6 章结构：
  - 第一章 绪论
  - 第二章 相关技术与理论基础
  - 第三章 系统需求分析
  - 第四章 系统总体设计
  - 第五章 系统详细设计与实现
  - 第六章 系统测试与部署
- 每章、结论、参考文献、致谢从奇数页开始
- 摘要与正文使用分离的 Roman / Arabic 页码体系
- 最终 `.docx` 默认应支持正文引用跳转到参考文献

### 基础要求与增强项

#### 提交基础要求

- 目录由 Word 自动生成
- Word 分节、页眉页码正确
- 正文引用在最终 `.docx` 中可点击跳转到参考文献
- 图表按章编号，正文中存在对应引用

#### 终稿增强项

- 图正文引用可点击跳转到图题
- 表正文引用可点击跳转到表题
- 图表素材批量插入与图块间距自动整理

当前证据只足以证明“正文引用跳转参考文献”是合规终稿里的基线能力，不足以证明“图表点击跳转”是提交必做项，因此图表交叉引用默认保留为按需增强。

### 与其他 Skill 的配合

- **$doc**：处理 `.docx`、分节、页眉页脚、页码、目录刷新和最终检查
- **$drawio**：处理架构图、ER 图、流程图等论文图表
- **$playwright-cli**：处理页面截图、流程证据和运行时证明

### 典型工作流

1. 先收集真实项目证据。
2. 先建立 `compliance matrix` 和 `evidence map`。
3. 默认按提交版兼容的 6 章结构逐章生成或修订内容。
4. 最后处理 Word 分节、页眉页码、目录和正文引用交叉引用。
5. 提交前做一次合规审查。
