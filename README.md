# gzcu-thesis-spec-skills

广州城市理工学院本科毕业设计（论文）写作、排版与合规检查 Skill。

本仓库的目标是把规则收敛到两类来源：

- 学校 `附件4-1：毕业设计（论文）格式规范.doc`
- 一份已提交版 `.docx` 样本，用作可参考基线

这不是论文生产流水线仓库，不负责截图取证、Draw.io 出图、资产装配、跨技能编排或默认 Word 自动化增强。

## 这个 Skill 做什么

- 解释学校论文格式规范
- 按学校规则生成论文结构建议、章节写作约束和排版要求
- 审查现有论文是否符合学校要求
- 在需要时参考提交版 `.docx` 的稳定实现方式，给出更接近终稿的 Word 建议

## 这个 Skill 不做什么

- 不默认要求浏览器截图、运行证据采集或页面取证
- 不默认要求 Draw.io 图示流程
- 不默认要求参考文献、图表的可点击交叉引用
- 不内置论文资产装配、批量插图或图片段落自动整理流程
- 不把提交版样本里的具体实现细节一律上升为学校硬规则

## 规则依据

### 一手依据

学校 `附件4-1：毕业设计（论文）格式规范.doc` 是最高优先级来源，主要用于确认：

- 摘要与关键词
- 目录
- 正文标题层级
- 字体字号与行距
- 图表位置与编号
- 参考文献格式
- 致谢格式

### 参考基线

提交版 `.docx` 只作为参考样本，用于补充更具体的默认建议，例如：

- 4 段分节
- 软件工程论文常见 6 章结构
- 摘要 Roman 页码与正文 Arabic 页码切换
- 奇偶页眉机制

这些内容是“可参考基线”，不是自动等同于学校硬规则。

## 推荐使用方式

### 1. 先做规则矩阵

```text
使用 $gzcu-thesis-spec，根据广州城市理工学院论文格式规范，先给我一份学校规则矩阵，并标出我的论文当前最容易出错的部分。
```

### 2. 再写章节

```text
使用 $gzcu-thesis-spec，根据学校要求和我的项目材料，先给出当前论文结构适配点，再撰写第二章内容。
```

### 3. 最后检查 Word 格式

```text
使用 $gzcu-thesis-spec，检查这篇论文是否符合摘要、目录、标题层级、图表、参考文献、页码和奇数页起章要求。
```

## 基线检查脚本

仓库保留 `gzcu-thesis-spec/scripts/check_docx_baseline.py`，其作用是辅助核对真实 `.docx` 是否接近提交版样本的结构基线。

它不是 Skill 主体，也不代表学校唯一合法实现。脚本检查结果应与学校 `.doc` 规则一起判断。

## 维护原则

- 学校 `.doc` 高于提交版 `.docx`
- 结构与排版规则优先于扩展自动化
- 默认回答先给“学校规则矩阵 + 当前论文适配点”，再给正文或排版建议
- 不把样本中的单一实现细节写成绝对化要求
