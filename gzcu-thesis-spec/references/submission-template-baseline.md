# Submission Template Baseline

Use this file only when a submitted sample `.docx` is relevant as a comparison baseline.

This file does not override the school format document. It records stable observations from one submitted sample and should be used as a secondary reference.

## 1. Evidence level

- Source type: submitted sample `.docx`
- Priority: lower than the school format document
- Use case: provide more concrete default suggestions when the school document is broad

## 2. Observed order

The sample manuscript follows this order:

1. cover page
2. declaration / authorization pages
3. Chinese abstract
4. English abstract
5. TOC
6. body chapters
7. conclusion
8. references
9. acknowledgements

## 3. Observed software-engineering chapter pattern

The sample uses this 6-chapter software-engineering structure:

1. 第一章 绪论
2. 第二章 相关技术与理论基础
3. 第三章 系统需求分析
4. 第四章 系统总体设计
5. 第五章 系统详细设计与实现
6. 第六章 系统测试与部署

Use this as a sample-compatible default only when it fits the user's project and no newer mandatory structure is provided.

## 4. Observed section and numbering pattern

The sample is consistent with a 4-section Word model:

1. cover + declaration pages
2. Chinese abstract + English abstract
3. TOC
4. main body through acknowledgements

Observed numbering behavior:

- abstract pages use Roman numerals,
- TOC is separated from the main body,
- Chapter 1 starts Arabic numbering,
- conclusion, references, and acknowledgements continue the main numbering.

## 5. Observed header pattern

The sample uses a main-body odd/even header mechanism:

- even-page header: `广州城市理工学院本科毕业设计（论文）`
- odd-page header follows the current chapter heading

The sample XML shows `STYLEREF` in an odd-page header definition. Treat this as one observed implementation method, not as a mandatory school rule.

## 6. What this baseline can support

This baseline can support:

- default Word-layout suggestions,
- review of sample-alignment issues,
- software-engineering chapter recommendations,
- section and page-number implementation advice.

## 7. What this baseline cannot prove

This baseline alone cannot prove:

- that all theses must use the same 6-chapter structure,
- that `STYLEREF` is the only legal odd-header implementation,
- that clickable bibliography, figure, or table cross-references are school hard requirements,
- that every paragraph-level visual detail in the sample is universally mandatory.
