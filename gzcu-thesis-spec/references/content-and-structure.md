# Content and Structure Rules

Use this file when drafting or reviewing thesis content.

Evidence priority:

1. school format document,
2. submitted sample `.docx` baseline.

## 1. Scope

- Apply thesis structure and formatting rules starting from the Chinese abstract page.
- Keep the cover page and the school declaration pages aligned with the school template.
- Keep the body in formal written language.
- Do not use first-person narrative in the body. Acknowledgements may use first person.

## 2. Abstract and keywords

### Chinese abstract

- Keep the Chinese abstract within `400-600` words/characters.
- Keep keywords to `3-5`.
- Use semicolons between keywords.
- Do not cite references in the abstract.
- Chinese abstract and keywords should occupy one page.

### English abstract

- The English abstract should be a faithful translation of the Chinese abstract.
- Keep keywords to `3-5`.
- Do not add extra claims or omit major points from the Chinese abstract.
- Do not cite references in the English abstract.
- English abstract and keywords should occupy one page.

## 3. Main structure

The school document confirms this overall order:

1. Chinese abstract
2. English abstract
3. TOC
4. body chapters
5. conclusion
6. references
7. acknowledgements

For software-engineering theses, the submitted sample supports this as a reference structure:

1. 第一章 绪论
2. 第二章 相关技术与理论基础
3. 第三章 系统需求分析
4. 第四章 系统总体设计
5. 第五章 系统详细设计与实现
6. 第六章 系统测试与部署

This 6-chapter structure is a recommended sample-compatible default, not the only legal structure for all topics.

## 4. Heading hierarchy

- Body chapters use `第一章、第二章、第三章……`
- Second level uses `1.1、1.2、1.3……`
- Third level uses `1.2.1、1.2.2、1.2.3……`
- Do not leave a heading as the last line on a page.

## 5. Body content rules

- Each chapter should have complete substance, not only a heading skeleton.
- Paragraph text should be the main carrier of explanation.
- Figures, tables, and code screenshots support the prose and should be explained in text.
- Avoid long raw code blocks in the body.
- If code must be shown, prefer white-background screenshots.

## 6. Figures and tables

- Every figure and table must have a caption.
- Figure captions go below the figure.
- Table captions go above the table.
- Number figures and tables by chapter, such as `图1-1` and `表1-1`.
- Every figure and table must be cited in the body.
- Tables spanning multiple pages should repeat the header and use `（续）` on the continued title.

## 7. References

- Reference numbering starts from `[1]`.
- The references list order must match the order of first appearance in the body.
- Use the school document's reference entry formats.
- Journal `[J]` and monograph `[M]` entries should include page ranges.
- Do not cite references in the abstract.

The previous repository version treated clickable bibliography jumping as a default baseline. That is no longer a default requirement in this skill unless the user explicitly asks for Word automation enhancement.

## 8. Conclusion and acknowledgements

### Conclusion

- The conclusion should summarize completed work, achieved results, limitations, and future improvements.
- Do not fill the conclusion with personal feelings.
- Do not cite references in the conclusion unless the user explicitly provides a separate approved requirement.

### Acknowledgements

- Acknowledgements should use a sincere and factual tone.
- The supervisor's full name should appear.

## 9. Drafting checklist

Before delivering drafted content, confirm:

- abstract length and keyword count are compliant,
- heading hierarchy is correct,
- chapter wording is formal,
- figures and tables are explained in prose,
- reference numbering logic is correct,
- conclusion and acknowledgements follow the school style,
- sample-based structure suggestions are not overstated as school hard rules.
