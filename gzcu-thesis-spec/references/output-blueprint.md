# Output Blueprint

Use this file when the user wants stable, reusable output templates instead of ad hoc prose.

The templates below are aligned to the compliant submission-ready chapter organization and Word implementation pattern.

## 1. Standard delivery package

Prefer this order unless the user asks for a narrower artifact:

1. Assumptions
2. Compliance matrix
3. Requested thesis artifact
4. Word-specific implementation notes, if layout matters
5. Manual replacement and review checklist

If the task includes `.docx` finalization, item 4 must explicitly mention the 4-section Word model, header rules, page-number rules, TOC refresh, odd-page chapter starts, and reference-cross-reference handling.

## 2. Abstract template

Use this structure when drafting Chinese and English abstracts:

```text
摘  要
[400-600 字。只写项目目标、方法、实现、结果与意义。不写背景铺垫，不引用文献。]

关键词：关键词1；关键词2；关键词3；关键词4

Abstract
[Chinese abstract 的准确英文翻译。不新增事实，不引用文献。]

Key words: keyword 1; keyword 2; keyword 3; keyword 4
```

Rules:

- Keep Chinese abstract within `400-600` words/characters.
- Keep `3-5` keywords.
- Use semicolons between keywords.
- Do not place punctuation after the last keyword.
- Keep Chinese and English abstracts factually aligned.

## 3. TOC template

When the user asks for a TOC plan or a machine-copyable heading map, use this structure:

```text
摘  要
Abstract
目  录
第一章 绪论
1.1 选题背景与研究意义
1.2 国内外研究现状
1.3 本文研究内容与目标
1.4 论文结构
1.5 本章小结
第二章 相关技术与理论基础
2.1 前后端分离开发架构
2.2 核心技术或理论基础
2.3 关键机制分析
2.4 本章小结
第三章 系统需求分析
3.1 系统目标与用户角色
3.2 功能需求分析
3.3 非功能需求分析
3.4 关键业务流程分析
3.5 本章小结
第四章 系统总体设计
4.1 系统总体架构设计
4.2 功能模块设计
4.3 数据库设计
4.4 接口设计
4.5 本章小结
第五章 系统详细设计与实现
5.1 核心模块实现
5.2 关键业务流程实现
5.3 关键算法与实现说明
5.4 本章小结
第六章 系统测试与部署
6.1 测试环境与测试策略
6.2 功能测试与结果分析
6.3 性能测试与结果分析
6.4 部署过程与运行支撑
6.5 本章小结
结  论
参考文献
致  谢
```

Rules:

- This is a planning template, not a substitute for Word-generated TOC.
- The final TOC must be generated by Word and include 3 levels.
- Keep `本章小结` as the last section of every body chapter.
- Testing and deployment may still be split into two chapters if the user has a newer mandatory template, but the compliant submission template above should be the default.

## 4. Chapter draft template

Use this output frame for a chapter or section draft:

```text
假设
- [列出项目材料中已知事实]
- [列出仍需用户确认的少量缺口]

适用规则
- [列出当前章节必须遵守的学校规则]

正文
第三章 系统需求分析
3.1 系统目标与用户角色
[正式书面语正文，围绕真实项目展开]

3.2 功能需求分析
[按模块或流程展开，不写空泛教材内容]

3.3 非功能需求分析
[性能、安全、可维护性、部署等]

3.4 关键业务流程分析
[说明流程、图表引用、设计理由]

3.5 本章小结
[只总结本章，不引入新内容，不引用文献]

人工补充项
- [截图、图表、真实数据、导师姓名、测试记录等]
```

Rules:

- Keep headings explicit and copyable into Word.
- Use prose first, figures/tables second.
- When references are needed, cite only in the body and keep citation order auditable.
- Do not put citations in `本章小结`.

## 5. Review report template

Use this structure when checking an existing thesis:

```text
Findings
1. [Highest-severity issue]
Rule: [具体学校规则]
Impact: [为什么不合规]
Fix: [如何修改]

2. [Next issue]
Rule: ...
Impact: ...
Fix: ...

Rule coverage
- [已满足的关键规则]
- [未满足的关键规则]

Manual checks
- [必须在 Word 中人工复核的项目]

Open risks
- [仍依赖模板、分页、目录域、导师全名等人工信息的风险]
```

Rules:

- Findings first, ordered by severity.
- Tie each finding to a school rule, not a generic style suggestion.
- Call out manual Word-only checks separately.

## 6. Word implementation template

Use this structure when the user wants finalization guidance for Word:

```text
假设
- [封面和说明页保持原样]
- [从摘要页开始执行格式规则]

Word 处理步骤
1. 分节
- [封面+说明页 / 中英文摘要 / 目录 / 正文至致谢 四段结构]
- [正文至致谢使用同一套奇偶页页眉和阿拉伯页码]

2. 页眉
- [摘要和目录无可见页眉]
- [偶数页固定页眉]
- [奇数页使用一级标题 STYLEREF]
- [页眉线 1.5 磅]

3. 页码
- [摘要 Roman，从 I 开始]
- [目录隐藏页码]
- [正文起阿拉伯数字 1]
- [结论、参考文献、致谢连续编号]

4. 奇数页起章
- [检查每章起始页]
- [必要时插入空白过渡页]

5. 图表与引用
- [图题下置，表题上置]
- [图表正文引用必须存在]
- [正文引用优先做成可点击参考文献交叉引用]
- [图表交叉引用仅在用户明确要求时增强]

6. 最终核查
- [目录更新]
- [分页复核]
- [页眉页码复核]
- [引用与参考文献顺序复核]
```

## 7. Final manual checklist template

End deliverables with a checklist similar to:

```text
人工复核项
- 封面和说明页是否完全保持学校模板原样
- 中文摘要、英文摘要、目录、正文至致谢是否按四段结构正确分节
- 目录是否由 Word 自动生成且已更新到 3 级
- 摘要是否无引用且中文摘要控制在 400-600 字
- 英文摘要是否为中文摘要准确翻译
- 每章是否另起页且从奇数页开始
- 必要的空白过渡页是否已插入
- 正文奇偶页页眉是否正确，奇数页是否跟随一级标题
- 页眉线是否为 1.5 磅
- 页码是否按 Roman / Arabic 正确分离并连续
- 正文是否无第一人称和口语化表达
- 每章末尾是否都有本章小结
- 本章小结和结论是否无参考文献引用
- 图表是否都有正文引用和按章编号
- 表格是否无两侧竖线、跨页时是否标“续”并重复表头
- 代码展示是否全部为白底截图
- 参考文献是否至少 12 篇且英文文献不少于 2 篇
- 参考文献顺序是否与正文首次引用顺序一致
- 正文引用是否已做成可点击参考文献交叉引用
- [J] / [M] 是否包含页码范围
- 致谢中是否已写入导师全名
```
